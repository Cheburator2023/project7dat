Алгоритм применения коммита к текущей модели данных

Цель. Требуется применить (добавить/обновить) к JSON файлу описания текущей модели данных (основе) все изменения из JSON файла коммита (сущностей, их атрибутов и связей). В результате слияния двух JSON файлов должен получиться JSON файл с обновленной версией описания модели данных.

Предусловия. S2T файл загружен в систему, преобразован в JSON файл обновления прошёл все проверки.

Заголовок desc

1. В заголовке JSON файла коммита сервис считывает и запоминает наименование процесса, это подстрока до точки в строке значения поля desc.appName.

1. Подпроцесс обновления массива объектов entities

2. Сервис считывает в JSON коммита очередной объект массива entities, запоминает уникальное наименование сущности entities.id.

3. Сервис ищет в массиве entities JSON основы объект с равным наименованием сущности в entities.id.

3. 3.1. Если в массиве entities JSON основы найден объект с эквивалентным наименованием сущности, сервис должен добавить в этом объекте в массив его атрибутов attrSeq все новые атрибуты одноименной сущности из массива атрибутов attrSeq коммита.

3. 3.2. Если в массиве entities JSON основы НЕ найден объект с эквивалентным наименованием сущности, сервис должен добавить в конце массива entities JSON основы весь объектэтой сущностиизкоммита.

4. После обработки последнего объекта массива entities JSON коммита подпроцесс обновления массива entities JSON основы завершается. Переход на шаг 5 Подпроцесса обновления массива маппинга атрибутов mappings.

4. Подпроцесс обновления массива маппинга атрибутов mappings

5. Сервис считывает в JSON коммита очередной объект массива связей сущностей mappings и запоминает уникальное наименование целевой сущности mappings.entityId этой связи

6. Сервис ищет в массиве связей сущностей mappings JSON основы объект связи с равным наименованием сущности в mappings.entityId

6. 6.1. Если в массиве mappings JSON основы найден объект связей сущностей с эквивалентным наименованием сущности:

6. 6.1.1 Если наименование процесса коммита (см. Шаг 1.) совпадает с наименование процесса объекта связи сущностей mappings.process , сервис должен удалить в файле основы массив связей атрибутов mappings.deps из объекта этой сущности и добавить в этот же объект массив связей атрибутов mappings.deps из объекта связи атрибутов коммита.

6. 6.1.2 Если наименование процесса коммита (см. Шаг 1.) НЕ совпадает с наименование процесса объекта связи mappings.process , сервис должен добавить в конец массива связей mappings JSON основы новый объект связей сущностей из коммита с дополнительными полями process и processId (этих полей нет в объекте коммита) . В поле mappings.process добавленного в основу объекта связисервис должен прописать наименование процесса коммита, идентификатор процесса processId должен быть пустым.

6. 6.2. Если в массиве mappings JSON основы НЕ найден объект связи с эквивалентным наименованием сущности, тогда сервис добавляет в конец массива mappings JSON основы объект этой связи из mappings коммита с дополнительными полями process и processId. В поле mappings.process объекта связисервис копирует наименование процесса коммита, идентификатор процесса processId должен быть пустым.

7. После обработки последнего объекта массива mappings JSON коммита подпроцесс обновления массива mappings JSON основы завершается.

8. Обработка JSON файла коммита завершена. Все обновления из коммита внесены в JSON файла основы. Процесс завершён.
