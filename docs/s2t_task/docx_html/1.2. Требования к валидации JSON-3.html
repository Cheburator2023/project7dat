Требования к валидации JSON файлов

Требование

Описание отклика системы

Файл полностью не соответствует схеме. Пользователю требуется корректировать файл.

API возвращает ошибку 400

Проверка на соответствие типов данных в полях JSON типам в схеме

1. Типы данных корректны и нет прочих ошибок - API возвращает 200 или 201

2. Типы данных некорректны - API возвращает 400

Файл частично не соответствует схеме. Например, витрина без атрибутов или атрибуты к несуществующей витрине и т.д. Требуется корректировать файл.

API возвращает ошибку 400

Ограничение на размер файла инкремента (защита от загрузки всей схемы)

API возвращает ошибку 413

Проверка типов данных атрибутов и типов их использования (where, join etc.)

1. Типы данных атрибутов корректны и нет прочих ошибок - API возвращает 200 или 201

2. Типы данных атрибутов некорректны - API возвращает 400

Рекурсия. Сущности таблицы могут дублироваться в файле с разными (зеркальными) значениями поля modify. Одни и те же сущности записаны как источники (modify = false) и как целевые сущности (modify = true). Требуется отслеживать случаи подобной рекурсии и удалять некорректные части файла.

При обнаружении рекурсии обновление данных в БД не проводится. API возвращает ошибку 400.

Проверка на рекурсию после добавления любой новой информации в базу

При обнаружении рекурсии обновление данных в БД не проводится. API возвращает ошибку 400.

Дублирование сущностей и их атрибутов в файле. Описания target - источник + атрибуты в файле могут дублироваться. Требуется удалить дубликаты из файла.

API возвращает ошибку 400

Проверка на корректный нейминг объектов (все имена объектов написаны кириллицей и содержат только разрешенные символы)

1. Имена объектов корректны и нет прочих ошибок - API возвращает 200 или 201

2. Имена объектов некорректны - API возвращает 400
