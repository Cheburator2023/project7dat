**1\. Авторизация**

Все пользователи авторизованные в СУМ должны иметь право на просмотр всех данных в DL (используется тот же access token JWT). На этапе MVP редактирование данных в DL не предусмотрено. Пользователь с ролью "Архитектор данных" имеет права на загрузку и подтверждение коммитов в DL.

В дальнейших версиях DL права пользователя на редактирование данных модели должны определяться по таблице соответствия наименования стримов схемам (namespace).

**2-3. Загрузка файла JSON (коммита) в очередь системы**

Цель. Пользователь хочет загрузить в систему файл коммита в формате JSON. Система должна проверить и сохранить файл обновления в своей очереди коммитов.

Предусловия. Пользователь авторизован в системе и находится в главном окне GUI.

Основной сценарий: Загрузка нового файла обновления (коммита) в очередь

1\. Пользователь выбирает в основном меню главного окна системы раздел «Коммиты», открывается окно «Очередь коммитов» с очередью непримененных (несмерженных) обновлений. В окне отображается список с очередью необработанных (несмерженных) загруженных файлов коммитов. Обновления отсортированы в порядке возрастания времени загрузки файла, сверху самые давние. Для каждого обновления указаны наименование, автор, статус, дата загрузки и тип файла. ~~Не прошедшие валидацию коммиты должны быть выделены ("подсвечены") в списке коммитов.~~

2\. Пользователь нажимает кнопку «Добавить», в открывшемся диалоговом окне выбирает локальный json файл и подтверждает его загрузку

3\. Отображается модальное диалоговое окно для внесения пользователем дополнительной информации об обновлении. Пользователь заполняет в редактируемых текстовых полях диалога наименование обновления (коммита) и его описание. По умолчанию поле с наименованием заполнено именем процесса 

4\. Пользователь подтверждает загрузку поименованного обновления с описанием. Диалоговое окно закрывается.

5\. Фронт системы выполняет предварительные проверки загружаемого файл на соответствие формату ( json) и на максимальный размер (< 1 Мб)4.1. Ели файл не проходит предварительную проверку на фронте пользователю отображается диалоговое окно с сообщением об ошибке ("Тип файла не является корректным, загрузите новый файл"/"Превышен максимальный размер файла, загрузите новый файл"). Файл не загружается. Сценарий завершается.4.2. Ели файл проходит предварительную проверку на фронте файл направляется на проверку в бэк-сервис

6\. Бэк-сервис выполняет валидацию файла

6.1. Если файл не прошел проверку пользователю отображается диалоговое окно с сообщением об ошибке (подробнее см. [6\. Работа с очередями и коммитамиhttps://sfera.inno.local/knowledge/pages?id=1651619](https://sfera.inno.local/knowledge/pages?id=1651619) ). Файл не загружается. Сценарий завершается.

6.2. Ели файл проходит проверку сервис сохраняет его в БДс новым уникальным идентификатором и статусом проверки. Бэкенд возвращает на фронт статус проверки файла.

6.3. Отображается диалог с и подтверждением постановки инкремента в очередь.

6.4. В конце списка коммитов в окне отображается новая запись коммита с указанием его текущего статуса "Исходный".

Дополнительный сценарий 1: Редактирование наименования и описания коммита из очереди

1\. Пользователь выбирает запись коммита в очереди коммитов и нажимает кнопку "Метаданные" диалога. Отображается модальное окно диалога с текущими наименованием и описанием коммита.

2\. Пользователь редактирует данные о подтверждает их кнопкой "ОК"

3\. Данные коммита в очереди изменились.

При выборе пользователем записи из списка сущностей в окнах json (diff-окна) отображается код изменений было-стало для этой сущности (таблица/view/файл json), включая атрибуты и связи. Для новых источников/витрин отображается только одно json окно коммита ("стало").

Кнопки (">>>", "<<<") позволяют перемещаться в JSON между изменениями для выбранного в списке объекта (источник/витрина)

**12.1. Целевой алгоритм сравнения для построения DIFF**

**Цель**: Требуется сравнить сущности (источники, витрины в **entities** ) и их связи (mapping) в JSON файле коммита с одноименными сущностями в целевом JSON файле с актуальными данными моделей. Результат сравнения с различиями, включая новые сущности, их атрибуты и связи, отобразить в двух окнах сравнения DIFF- "было" и "стало".

Ключи для сравнения сущностейd JSON:

**entities.id** - уникальное наименование сущности в разделе атрибутов (признаков)

**mappings.entityId** - уникальное наименование сущности в разделе маппинга атрибутов

2\. Если сущность с **entities.id** из JSON коммита отсутствует в целевом JSON с актуальными данными моделей, тогда она определяется как новая сущность и не подлежит сравнению, все её атрибуты и маппинг помещаются в разделе "стало" DIFF.

2\. Если в целевом JSON в массиве объектов **entities** найдена сущность с тем же значением **entities.id** что и в коммите, требуется в коммите и целевом JSON :

2\. 2.1. Сравнить вид (источник/таргет) в поле **entities.modified** и тип объекта в поле **entities.type** (table/view).

2\. 2.2. Сравнить все атрибуты из массива **entities.attrSeq.** Атрибуты объекта сравниваются по их полному наименованию **entities.attrSeq.name** и типу данных **entities.attrSeq.name** (т.е. атрибуты "inn" и "inn_t" должны сравниваться как разные атрибуты объекта, а не как изменение имени атрибута "inn" на атрибут "inn_t"). Отмечаются новые и отсутствующие атрибуты, одноименные атрибуты с разными типами и/или комментариями.

2\. 2.3. Сравнить маппинг сущности в разделе **mappings:**

2\. 2.3.1 Если сущность витрина (**entities.modified = true**), тогда сравнивать надо маппинг витрины на её источники при условии **mappings.entityId=entities.id.**

2\. 2.3.1. Сравнить массивы источников витрины **mappings.deps.entityId (**имя источника витрины **).**

2\. 2.3.1.1. Сравнить маппинг атрибутов витрина-источник в массиве маппинга атрибутов **mappings.deps.attrMaps (**где **dst** атрибут витрины (target)**, src** атрибут источника**).** Атрибуты объекта сравниваются по их полному наименованию.

2\. 2.3.1.2. Сравнить атрибуты источника и их функции в массиве **mappings.deps.attrDeps (**где **attr** атрибут источника**, linkTypes** массив функций атрибутаисточника**).** Атрибуты объекта сравниваются по их полному наименованию.
